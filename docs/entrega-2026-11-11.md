# VivaFinanças — entrega escolar (Etapa 7)

Documento da entrega da atividade escolar: o que o app faz hoje, onde ele está, o que já foi
verificado, o que ainda depende de credenciais e um roteiro de apresentação de 5 a 10 minutos.

Data da entrega: 11/11/2026.

## 1. O que é

VivaFinanças é um app de gestão financeira familiar. Uma família compartilha o mês: cada pessoa
lança receitas e despesas, confirma as contas recorrentes, acompanha metas e vê a previsão dos
próximos meses. A Jev AI ajuda a classificar um lançamento e sugere o que fazer com o dinheiro.

- **Web**: SPA React em `https://trabalho-terceiro-trimestre-vivafinancas.vercel.app`, servida pela
  Vercel junto com a API Flask.
- **Android**: o mesmo SPA é empacotado com Capacitor e distribuído como APK. A configuração está
  em `frontend/capacitor.config.json` (`com.vivafinancas.app`) e o deep link
  `vivafinancas://reset-password` já tem teste. O projeto nativo `android/` e o APK assinado ainda
  não estão no repositório nesta data — é a pendência aberta da entrega (seção 9).

Não é um produto em produção: é uma entrega escolar, com uma família de teste e integrações
demonstráveis.

## 3. Escopo entregue

- **Login e sessão**: Supabase Auth com confirmação de e-mail; recuperação de senha; convite de
  membro pela tela de configurações.
- **Painel**: saldo do mês, receitas, despesas, acumulado de 6 meses, despesas por categoria,
  metas da família, contas a confirmar, sugestões da Jev e alertas do dia.
- **Lançamentos**: criar, editar e excluir; categoria sugerida pela Jev enquanto você digita a
  descrição; escopo pessoal ou família.
- **Recorrentes**: regras mensais e fila de confirmação do mês; confirmar cria o lançamento de
  forma atômica, ignorar fecha o mês sem ele.
- **Metas**: meta da família ou pessoal, com contribuições (a contribuição não vira lançamento).
- **Previsão**: 12 meses, com gráfico mês a mês e detalhamento de recorrentes versus variável.
- **Jev AI**: classificação de descrição e sugestões estruturadas (o que fazer, por quê, quanto).
  Não há página de chat.
- **Extrato e banking**: conexões pessoais, saldos, transações do banco, sincronização,
  importação, reconciliação com lançamento existente, ignorar e desfazer.
- **Configurações**: perfil e tema, membros (admin), convites (admin), categorias e contas
  bancárias.
- **E-mail**: confirmação de cadastro, convite e redefinição de senha, todos passando por
  `/auth/confirm` com `verifyOtp({ token_hash, type })`.
- **Pluggy**: `POST /api/banking/connect_token` com `options.clientUserId`, auth
  `clientId`/`clientSecret` com cache, widget real no frontend (`cdn.pluggy.ai/pluggy-connect`),
  sync paginado em `/v2/transactions`.
- **APK**: pendente (ver seção 9).

## 4. Arquitetura em 10 linhas

1. **Frontend**: React 18 + Vite + Tailwind 4 + Recharts, SPA mobile-first, tema claro/escuro.
2. **Backend**: Flask exposto como Vercel Service, com todas as rotas em `/api` e
   `maxDuration` de 300 s.
3. **Um projeto só**: `vercel.json` sobe backend e frontend e reescreve `/api/*` para o Flask.
4. **Banco**: Supabase/Postgres 17.11 com RLS por membro; o RLS é a fonte da verdade do acesso.
5. **Autenticação**: JWT do usuário em toda leitura/escrita normal; service role só na Admin API
   de convites e no sync Pluggy.
6. **Auth e e-mail**: Supabase Auth com SMTP da Mailjet (remetente único verificado).
7. **IA**: `OpenCodeGoAdapter` sobre `https://opencode.ai/inference/go/openai/v1`, modelo
   `deepseek-v4.1-flash`, resposta em JSON e fallback determinístico.
8. **Banking**: Pluggy (`/auth` com cache → `POST /connect_token` → widget → item → sync).
9. **Regra do lançamento bancário**: transação de banco nunca cria lançamento sozinha; importar
   ou reconciliar é sempre um clique explícito.
10. **Deploy**: um único deploy na Vercel serve o SPA e a API no mesmo domínio.

### Deploy por git (projeto novo, sem MCP)

O build de deploy não depende de envs cadastradas no painel para o frontend: `frontend/.env.production`
versiona `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` e `VITE_API_URL=/api`. As duas primeiras são
públicas por design (vão no bundle do navegador) e é o RLS que protege os dados.

No projeto da Vercel: framework preset **Services**, root directory na raiz do repositório. Com isso o
`vercel.json` sobe os dois serviços e o `/api/*` cai no Flask.

Cadastre estas envs (Production e Preview) para as integrações que dependem de segredo — sem elas o app
funciona, mas convite, IA real e banking ficam desligados:

| Env | Efeito sem ela |
|---|---|
| `SUPABASE_SERVICE_ROLE_KEY` | convites e sync Pluggy respondem 503 |
| `JEV_AI_API_KEY`, `JEV_AI_SESSION` | Jev AI cai no fallback determinístico |
| `PLUGGY_CLIENT_ID`, `PLUGGY_CLIENT_SECRET` | `/banking/connect_token` responde 503 |

Opcionais com default no código: `JEV_AI_BASE_URL`, `JEV_AI_MODEL` (`deepseek-v4.1-flash`),
`JEV_AI_PROVIDER` (`opencode`), `SEED_DIR` (`seed`), `FLASK_ENV` (`production`), `CORS_ORIGINS`,
`PUBLIC_SITE_URL` e `SUPABASE_URL`/`SUPABASE_ANON_KEY` (públicas, com default do projeto).

## 5. Como rodar local

Pré-requisitos: Python 3, Node, `.venv` na raiz do repositório e um projeto Supabase com as
migrations e o seed aplicados. PowerShell é o shell documentado.

Backend (o `PYTHONPATH` é obrigatório, senão `app` não é importável):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
Copy-Item backend/.env.example backend/.env   # preencha as chaves
$env:PYTHONPATH='backend'
.\.venv\Scripts\python.exe -m pytest -q backend/tests
.\.venv\Scripts\python.exe -m flask --app app run --port 5000
```

`GET http://127.0.0.1:5000/api/health` responde `{"ok":true}`.

Frontend:

```powershell
cd frontend
npm install
Copy-Item .env.example .env.local   # VITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY, VITE_API_URL
npm test
npm run build
npm run dev                          # porta 5173
```

E2E (precisa de backend na 5000, frontend na 5173, `frontend/.env.local`, demo no baseline e
Chrome instalado):

```powershell
cd frontend
npx playwright test e2e/v1.spec.js --project=desktop
npx playwright test e2e/v1.spec.js --project=mobile -g "painel"
```

O spec é serial e mexe na demo hospedada; se um run parar no meio, restaure a demo antes de
repetir.

## 7. Limitações e riscos

- **Supabase Free**: um único projeto, sem staging e **sem backup automático**. Se o projeto for
  apagado ou corrompido, não há restauração point-in-time.
- **Vercel Hobby**: uso não comercial e teto de execução de 300 s por requisição. O dashboard
  pode levar ~20 s no Supabase hospedado porque as RPCs rodam em série — é conhecido, não é
  regressão.
- **Mailjet Free**: 200 e-mails/dia e 6.000/mês. O SMTP do Supabase impõe 30 mensagens por hora
  por padrão (ajustável em Authentication → Rate Limits). O domínio `mineseedfinder.com` está
  autenticado (DKIM/SPF OK), então o remetente é `contact@mineseedfinder.com`.
- **Convites**: enquanto o SMTP do Supabase não estiver configurado, o projeto usa o SMTP embutido
  (2–4 e-mails/hora) e o convite falha com `email_rate_limited`. A API já devolve esse código com
  a instrução, em vez de uma mensagem genérica.
- **Pluggy Meu Pluggy**: a conta usada é pessoal e **não comercial**; o uso aqui é uma atividade
  escolar. O plano/limite do Meu Pluggy pode mudar sem aviso.
- **OpenCode Go**: é um plano pensado para agentes de código, não para uma aplicação de produção.
  Volume baixo, e o fallback determinístico assume se a chamada falhar.
- **Sem DKIM/domínio próprio**: e-mail de remetente único pode cair em spam. Alternativa: copiar
  o link do convite.
- **Demo pública removida**: atalhos de login só existem em desenvolvimento. Em produção, as
  credenciais da seção 2 são digitadas.
- **Sem push, Play Store, iOS e domínio próprio**: fora do escopo desta entrega.

## 8. Roteiro da apresentação (5–10 min)

Abra o app publicado em uma aba e o código/README em outra. A ordem abaixo conta uma história:
o mês da família, uma decisão com a Jev, o dinheiro que sai sozinho e o banco.

**1. Login com a Ana (30 s).**
Digite `ana@demo.vivafinancas.app` / `Demo@2026!`.
*Diga:* "É a conta admin da família de demonstração; os dados são fictícios."
*Se falhar:* confira se a sessão antiga expirou; recarregue e entre de novo.

**2. Painel (1 min).**
Mostre o saldo do mês, "Entraram", "Saíram", o acumulado de 6 meses e as despesas por categoria.
*Diga:* "O painel é o mês da família inteira, não só o meu."
*Se falhar:* o painel pode demorar ~20 s; aguarde antes de recarregar.

**3. Lançamento com classificação da Jev (1 min).**
Lançamentos → novo → digite "Padaria" e espere a categoria sugerida (Alimentação) → salve.
*Diga:* "A Jev lê a descrição e propõe a categoria; eu ainda confirmo."
*Se falhar:* sem chave da IA o fallback classifica por palavra-chave — a sugestão aparece igual,
com `mode: fallback`.

**4. Sugestões da Jev (1 min).**
Abra Jev AI → Sugestões. Cada card tem o que fazer, por quê e quanto. Marque uma como lida.
*Diga:* "Não é chat: são sugestões estruturadas sobre os números que já estão no app."
*Se falhar:* as sugestões do seed continuam na tela; a leitura é local.

**5. Recorrentes (1 min).**
Recorrentes → "Para confirmar" → confirme uma conta do mês (ou ignore outra).
*Diga:* "Confirmar cria o lançamento de uma vez; ignorar tira a conta deste mês sem apagar a regra."
*Se falhar:* a fila pode estar vazia se as contas já foram confirmadas; mostre as regras.

**6. Meta (30 s).**
Metas → contribua para uma meta.
*Diga:* "A contribuição entra no progresso, não vira lançamento."
*Se falhar:* mostre só o progresso e explique a regra.

**7. Previsões (1 min).**
Previsões → 12 meses → passe o mouse no gráfico e abra o detalhamento de um mês.
*Diga:* "A projeção separa o que é recorrente do que é variável."
*Se falhar:* a previsão é calculada no servidor; se der erro, siga para o banking e volte depois.

**8. Meu Pluggy e conexão (1 min).**
Extrato → "Contas conectadas" → "Conectar banco" (abre o widget da Pluggy com o connect token).
*Diga:* "O token é gerado no backend; o widget nunca vê a API key, e o app nunca vê a senha do banco."
*Se falhar:* a conexão de demonstração continua listada; use-a para os próximos dois passos.

**9. Importar (1 min).**
Selecione uma transação pendente → Importar.
*Diga:* "Importar cria o lançamento com `origem=pluggy`; o banco nunca cria lançamento sozinho."
*Se falhar:* importe a transação demo, que também passa pelo mesmo fluxo.

**10. Reconciliar (1 min).**
Abra outra transação pendente → Reconciliar → escolha o candidato por valor e data.
*Diga:* "Reconciliar liga a transação a um lançamento que já existe, em vez de duplicar."
*Se falhar:* mostre o candidato sugerido e explique a tolerância de ±0,01 e ±1 dia.

**11. Tema claro/escuro (20 s).**
O botão de tema no topo (ou Configurações → Perfil → Tema).
*Diga:* "O tema é por pessoa e persiste entre sessões."

**12. Convite por e-mail (quando a Mailjet estiver ativa) (1 min).**
Configurações → Convites → convidar um e-mail → abra a caixa e clique em "Aceitar convite".
O link passa por `/auth/confirm` (`type=invite`) e cai em `/invite/<token>`.
*Diga:* "O convite é do Supabase Auth com o SMTP da Mailjet; o token do convite é nosso."
*Se falhar:* copie o link do convite (botão "Copiar link" na lista de convites) e abra direto;
registre que o envio real ficou pendente.

Fechamento (20 s): "Tudo isso roda em um projeto Vercel e um Supabase Free — é entrega escolar,
não produção."
